# Dashboard Ozon — установка

Dashboard Ozon каждое утро сам забирает данные вашего магазина из Ozon и показывает, сколько вы заработали чистыми: по дням, по месяцам и по каждому товару. Он живёт целиком в ваших бесплатных аккаунтах GitHub и Cloudflare. Ничего не нужно ставить на компьютер, ничей чужой сервер не участвует, ваши ключи и цифры видите только вы.

**Что понадобится:** доступ владельца к кабинету продавца Ozon, почта, примерно час времени. Всё делается в браузере, одинаково на Mac и Windows. Удобнее с компьютера.

**Если закрыли вкладку и не знаете, куда вернуться:** GitHub — **github.com** (справа вверху значок вашего аккаунта → **Your repositories** → `dashboard-ozon`); Cloudflare — **dash.cloudflare.com** → слева **Compute** → **Workers & Pages** → `dashboard-ozon`. В каждом шаге ниже есть и прямые ссылки.

**Главное правило:** ключи, которые вы создадите, — как пароль от кабинета. Вставляйте их только туда, куда сказано в инструкции. Никому не пересылайте, в чаты не вставляйте. Пока идёте по шагам, можно держать их в заметке на своём компьютере, а в конце эту заметку удалить.

## Шаг 1. Ключи Ozon

### 1.1. Ключ продавца (обязательно)

1. Откройте **seller.ozon.ru** → **Настройки** → в разделе **API интеграции** выберите **Seller API**.
2. Нажмите **Сгенерировать ключ** (или **Добавить ключ**). Откроется окно «Генерация ключа».
3. **Название ключа:** `Dashboard Ozon`.
4. **Цель использования ключа** (обязательное поле): выберите **«Для личного использования»** — инструмент работает в ваших аккаунтах и только для вас.
5. В списке ролей прокрутите вниз, найдите **Admin read only** и поставьте галочку **только у неё** — это доступ только на чтение. Ключ с правом изменений этому инструменту не нужен и опасен.
6. Вкладку **«Разрешённые сети»** не заполняйте: GitHub каждый раз заходит с разных адресов, и ключ с привязкой к адресам работать не будет. Нажмите **Сгенерировать**.
7. Ozon покажет **Client-Id** (число) и **API-ключ** (длинная строка). Ключ показывается **один раз** — сразу сохраните оба значения в заметку.

### 1.2. Ключ рекламного кабинета (желательно)

Без него Dashboard не увидит расходы на рекламу, и прибыль будет завышена.

1. Там же, в **Настройки** → **API интеграции**, выберите **Performance API**. Ключи рекламы здесь живут внутри «сервисных аккаунтов»: сначала аккаунт, в нём — ключ.
2. Нажмите синюю кнопку **Создать аккаунт** справа вверху. Ozon ничего не спросит и ничего не покажет — просто вверху таблицы появится новая строка с номером аккаунта, сегодняшней датой и **0** в колонке «Кол-во ключей». Так и должно быть: аккаунт пока пустой.
3. Нажмите на **номер этого нового аккаунта** (в первой строке) — откроется сам аккаунт.
4. Внутри нажмите синюю кнопку **Добавить ключ**.
5. Появятся две строки — **Client ID** и **Client Secret**, справа у каждой кнопка «скопировать». Скопируйте обе по очереди в заметку. Secret показывается **один раз**.
6. Если в таблице уже есть другие сервисные аккаунты — не трогайте и не удаляйте их: ими могут пользоваться другие ваши сервисы.

## Шаг 2. Своя копия на GitHub

**Что здесь происходит.** На GitHub лежит образец — папка с программой Dashboard Ozon, открытая всем. Вы делаете себе её **копию** — свою папку, закрытую от всех, кроме вас. В вашей папке каждое утро сам будет просыпаться робот: заходить в Ozon с вашими ключами, всё считать и складывать результат туда же.

### 2.1. Зарегистрироваться на GitHub (если аккаунта ещё нет)

GitHub — бесплатный сервис, где хранятся программы. Аккаунт нужен один раз.

1. Откройте **https://github.com/signup** — регистрация.
2. GitHub по очереди спросит:
   - **Email** — ваша почта (на неё придёт код);
   - **Password** — придумайте пароль, не короче 8 знаков, с цифрой и маленькой буквой. Запишите его;
   - **Username** — имя пользователя латиницей, его называют **логин**. Например `ivanov-shop`. Он будет в адресах — запишите его, дальше понадобится;
   - **Country/Region** — ваша страна;
   - рассылку можно не отмечать.
3. Нажмите **Continue** / **Create account**. GitHub может попросить решить простую картинку-задачку — это проверка, что вы не робот.
4. На почту придёт письмо с **кодом** из 8 цифр — впишите его на странице GitHub.
5. Если после этого GitHub задаёт вопросы о вас («сколько человек в команде», «чем интересуетесь») — их можно пропустить (**Skip**). Если предлагает выбрать тариф — выбирайте бесплатный (**Free**).

**Как понять, что получилось:** вы на главной странице GitHub, справа вверху круглый значок — это ваш аккаунт.

### 2.2. Сделать копию образца

1. Убедитесь, что вошли в свой аккаунт GitHub (справа вверху ваш значок; если нет — **Sign in** и войдите с почтой и паролем).
2. Откройте ссылку: **https://github.com/nikitabuilding-code/dashboard-ozon/generate** — откроется форма «Create a new repository».

   **Не пугайтесь чужого имени в ссылке.** `nikitabuilding-code` — это автор образца, ссылка ведёт на образец, а не в чужой аккаунт. Копия создастся **в вашем** аккаунте: в поле **Owner** формы будет стоять ваш логин. Автор образца вашу копию не видит и ничего в ней не может изменить. Если GitHub вместо формы просит войти — войдите и откройте ссылку ещё раз.
3. Форма «Create a new repository» состоит из трёх частей. Сверху вниз:
   - **Start with a template** — там уже выбрано `nikitabuilding-code/dashboard-ozon`, переключатель **Include all branches** — Off. Ничего не трогайте;
   - раздел **1 General**:
     - **Owner** — там уже стоит ваш логин, не трогайте;
     - **Repository name** — впишите `dashboard-ozon`. Под полем появится зелёная надпись «dashboard-ozon is available» — значит, имя свободно;
     - **Description** — оставьте пустым;
   - раздел **2 Configuration** → **Choose visibility** — справа кнопка с выпадающим меню. Проверьте, что выбрано **Private** (с замочком): нажмите на кнопку, в меню отметьте **Private**. Не **Public** — в папке будут ваши цифры и закупочные цены.
4. Внизу нажмите зелёную кнопку **Create repository**.

**Как понять, что получилось:** откроется страница вашей копии, рядом с названием серая надпись **Private**. Адрес в браузере — github.com/**ваш-логин**/dashboard-ozon. Запишите себе этот адрес: дальше он понадобится.

## Шаг 3. Ключи Ozon — в сейф GitHub

**Что здесь происходит.** Робот берёт ключи из **секретов** — это закрытый сейф внутри вашей папки. Положили ключ туда — и даже вы его больше не увидите, его видит только робот.

1. Откройте ссылку, вписав в неё свой логин вместо слова ЛОГИН:
   **https://github.com/ЛОГИН/dashboard-ozon/settings/secrets/actions/new**
   Откроется форма с двумя полями. (Или так: в своей копии вкладка **Settings** → слева **Secrets and variables** → **Actions** → зелёная кнопка **New repository secret**.)
2. Поле **Name** — имя ключа из таблицы ниже, поле **Secret** — сам ключ из заметки. Потом зелёная кнопка **Add secret**.
3. Повторите четыре раза: на открывшейся странице каждый раз жмите зелёную **New repository secret**.

| Name (копируйте отсюда) | Secret (из заметки) |
|---|---|
| `OZON_CLIENT_ID` | Client-Id ключа продавца — число |
| `OZON_API_KEY` | API-ключ продавца — длинная строка |
| `OZON_PERF_CLIENT_ID` | Client ID рекламы — с «@» |
| `OZON_PERF_SECRET` | Client Secret рекламы |

Имена — точно так, большими латинскими буквами с подчёркиваниями. Лишний пробел в начале или в конце ключа его сломает.

**Как понять, что получилось:** в списке **Repository secrets** четыре строки с этими именами. Значений не видно — так и должно быть.

Если рекламного ключа нет — последние два пропустите, их можно добавить позже.

## Шаг 4. Первый запуск робота

**Что здесь происходит.** Робот сам будет просыпаться каждое утро. Но в первый раз его нужно разбудить вручную — чтобы он сразу забрал историю за 3 месяца и проверил, что ключи подходят.

1. Откройте ссылку, вписав свой логин вместо ЛОГИН:
   **https://github.com/ЛОГИН/dashboard-ozon/actions/workflows/sbor.yml**
   Если вместо страницы видите жёлтую плашку с кнопкой **I understand my workflows, go ahead and enable them** — нажмите её и откройте ссылку снова.
2. Откроется страница **«Сбор данных»**: слева список (выделено «Сбор данных»), в центре надпись «0 workflow runs» и «This workflow has no runs yet» — робот ещё ни разу не запускался. Сверху может висеть голубая плашка «Help us improve GitHub Actions» — не обращайте внимания.
3. Справа от заголовка «Сбор данных» — зелёная кнопка **Run workflow**. Нажмите её. Запуска ещё не будет: под кнопкой появится белая рамка с заголовком **«Use workflow from»**, в ней поле **main** и внизу две кнопки — серая **Cancel** и зелёная **Run workflow**.
4. Нажмите зелёную **Run workflow** внизу этой белой рамки (рядом с Cancel). Поле main не трогайте. Рамка закроется.
5. Через 5–10 секунд вместо «no runs yet» появится строка «Сбор данных» с **жёлтым кружком** — робот запущен. Нажмите на неё — откроется страница запуска «Сбор данных #1».
6. На этой странице в поле **Status** сначала стоит **Queued** — «в очереди»: GitHub ищет для робота свободную машину, от нескольких секунд до пары минут. Потом **In progress** — робот работает. **Первый раз это около 5 минут** (на пробной установке — 4 мин 37 с), если Ozon отвечает медленно — до 15. Каждое следующее утро робот докачивает только свежие дни и справляется за 1–2 минуты. Страницу можно не обновлять — статус сменится сам. Кнопку **Cancel workflow** справа вверху не нажимайте — она остановит робота.

**Как понять, что получилось:**
- **зелёная галочка** у строки — всё хорошо. Для уверенности нажмите на строку → **sbor** → раскройте шаг **«Сбор и расчёт»**: внизу будут строки «· товары: … в кабинете», «· начисления: обновлено дней …», «· реклама: кампаний …» и не будет строк со значком ⚠. Строка «новые товары без закупки» — нормальная подсказка: закупку впишете в шаге 7. Серые строки `DeprecationWarning` в самом низу — служебное предупреждение GitHub, на работу не влияют;
- **красный крестик** — нажмите на строку, откройте шаг с крестиком и пришлите снимок экрана тому, кто помогает с установкой. Чаще всего это опечатка в ключе (шаг 3).

## Шаг 5. Страница на Cloudflare

**Что здесь происходит.** Робот всё посчитал, но смотреть пока негде. Cloudflare — бесплатный сервис, который покажет результат красивой страницей по вашей личной ссылке, открывается и с компьютера, и с телефона. Cloudflare сам берёт файлы из вашей папки на GitHub и обновляет страницу каждый раз, когда робот что-то досчитал.

### 5.1. Зарегистрироваться на Cloudflare (если аккаунта ещё нет)

1. Откройте **https://dash.cloudflare.com/sign-up** — регистрация.
2. Впишите **Email** и придумайте **Password** (запишите его) → **Sign up** (или **Create account**). Может появиться проверка «я не робот» — отметьте галочку.
3. Cloudflare пришлёт письмо на почту — откройте его и нажмите ссылку подтверждения.
4. Если Cloudflare спрашивает, что вы хотите сделать, или предлагает подключить сайт/домен — пропустите: домен не нужен. Тариф бесплатный (**Free**), карту не просят.

**Как понять, что получилось:** вы в панели Cloudflare, слева меню (Account Home, Workers & Pages и другое).

### 5.2. Создать страницу

1. В меню слева, в разделе **Build**, нажмите **Compute** — он раскроется — и выберите **Workers & Pages**. Откроется страница «Workers & Pages». Справа вверху нажмите синюю кнопку **Create application**.
2. Откроется страница «Make something new» с несколькими вариантами. Нажмите первый — **Connect GitHub** (со значком кошки GitHub). Остальные варианты (Hello World, template, upload) не нужны.
3. Поверх Cloudflare откроется отдельное небольшое окно GitHub «Install & Authorize Cloudflare Workers and Pages» — GitHub спрашивает, к каким папкам пустить Cloudflare. **По умолчанию там отмечено «All repositories» — так не оставляйте.**
   - отметьте второй кружок **Only select repositories**;
   - под ним появится кнопка **Select repositories** — нажмите, откроется список ваших папок. Выберите свою копию `ваш-логин/dashboard-ozon` — с **замочком** (значит, закрытая). Если в списке есть другие папки — их не выбирайте;
   - кнопка **Install & Authorize** внизу была бледной — после выбора она станет ярко-зелёной;
   - нажмите её. Если GitHub попросит пароль или код подтверждения — введите.

   Так Cloudflare увидит только эту папку, остальное — нет. Разрешение «Read and write access to … code, deployments» в окне — обычное для Cloudflare: ему нужно забирать файлы. После нажатия **не переключайте вкладки**, пока окно не закроется само.

   **Как понять, что связь есть:** на странице «Make something new» кнопка называется уже **Continue with GitHub**, и у значка горит **зелёная точка**. Нажмите её.

   **Если окно показало «Error connecting to git account»** или после нажатия открывает главную страницу Cloudflare вместо списка папок — связь застряла на полпути. Так было на пробной установке, лечится так:
   1. Откройте **https://github.com/settings/installations** → у «Cloudflare Workers and Pages» нажмите **Configure** → в самом низу, в красной рамке «Danger zone», — **Uninstall** (не Suspend) → подтвердите. Через минуту обновите страницу (Cmd+R на Mac, F5 на Windows) — список должен стать пустым.
   2. Там же вкладка **Authorized GitHub Apps** → у «Cloudflare Workers and Pages» нажмите **Revoke** → подтвердите. Должно стать «No authorized GitHub Apps».
   3. Вернитесь на вкладку Cloudflare со страницей «Make something new», обновите её и повторите **Connect GitHub** с начала этого шага.
4. Откроется «Select a repository» — в списке ваша папка `dashboard-ozon`. Нажмите на неё, затем синюю **Next** справа внизу.
5. Откроется «Set up your application» — последний экран перед выкладкой:
   - **Project name** — должно быть ровно `dashboard-ozon`. Это имя записано внутри программы, и если они не совпадут, выкладка упадёт. Если ваша копия называется иначе и поле подставило другое имя — сотрите и впишите `dashboard-ozon`;
   - **Build command** — оставьте пустым;
   - **Deploy command** (`npx wrangler deploy`) и **Preview command** — не трогайте, как и всё ниже;
   - нажмите синюю **Deploy**.
6. Подождите 1–2 минуты. Cloudflare покажет адрес вида **https://dashboard-ozon.что-то.workers.dev** — это ваша ссылка. Сохраните её в закладки на компьютере и телефоне.

**Как понять, что получилось:** сначала на странице сборки «Build #…» у названия появится зелёная галочка (этапы Initializing → Cloning → Installing → Deploying, около минуты; кнопку Cancel build не трогайте). Потом ваша ссылка откроется белой страницей с одной строчкой «Задайте пароль: переменная PAROL в настройках Worker…». Это правильно: **на этой странице нажимать ничего не нужно** — она просто ждёт пароль, это следующий шаг. Добавьте ссылку в закладки и переходите к шагу 6.

## Шаг 6. Пароль и разрешение сохранять настройки

**Что здесь происходит.** Страницу нужно закрыть паролем, чтобы ваши цифры не увидел посторонний. И ещё дать странице «пропуск» в вашу папку на GitHub — чтобы на вкладке «Настройки» можно было менять закупку, налог и расходы прямо со страницы.

### 6.1. Пропуск в папку GitHub

1. Откройте ссылку: **https://github.com/settings/personal-access-tokens/new** — форма нового пропуска (по-английски «token»).
2. Заполните:
   - **Token name** — `Dashboard Ozon`;
   - **Expiration** — нажмите (по умолчанию «30 days»), выберите **Custom** и в появившемся поле даты поставьте дату **через год**. «No expiration» (бессрочно) не берите. Поставьте себе в календарь напоминание за неделю до конца — выпустить новый: когда пропуск истечёт, «Сохранить» на странице перестанет работать;
   - **Token name** — если GitHub пишет зелёным «is available», имя подходит;
   - **Description** — оставьте пустым; **Resource owner** — ваш логин, не трогайте;
   - **Repository access** — отметьте третий кружок **Only select repositories** → кнопка **Select repositories** → в списке галочка **только** у своей копии `dashboard-ozon` (с замочком) → закройте список крестиком. Ниже появится «Selected 1 repository»;
   - ниже раздел **Permissions** → кнопка **+ Add permissions** → в списке отметьте **Contents** и **Actions** (удобно через поиск). Они появятся строками с выбором **Access: Read-only** — у обоих переключите на **Read and write**. Строку **Metadata** (с пометкой Required) GitHub добавит сам — её не трогайте, ей хватает Read-only.

   **Не пугайтесь слова «write» (запись).** Этот пропуск — к вашей папке на GitHub, **не к кабинету Ozon**. Ключ Ozon вы создали в шаге 1 только на чтение — с ним ничего в кабинете изменить нельзя, и этот шаг его не меняет. А «запись» здесь нужна для двух вещей:
   - **Contents** — чтобы страница «Настройки» могла сохранить в вашу папку то, что вы ввели: закупку, налог, свои расходы. Без этого кнопка «Сохранить» не сработает;
   - **Actions** — чтобы кнопки «Пересчитать сейчас» и «Обновить инструмент» могли запустить робота в вашей папке, не дожидаясь утра.

   Пропуск действует **только на одну папку** (остальные ваши папки на GitHub ему недоступны), хранится в Cloudflare в закрытом виде, пользуется им только ваша страница после ввода вашего пароля.
3. Внизу зелёная кнопка **Generate token** → в окошке подтверждения ещё раз **Generate token**.
4. Появится строка, начинается с `github_pat_` — нажмите значок копирования справа и вставьте её в заметку. Показывается один раз. Снимок экрана с этой строкой не делайте и никому не отправляйте. Когда строка в заметке — вкладку GitHub можно закрыть.

### 6.2. Пароль и пропуск — в Cloudflare

1. Откройте настройки своей страницы в Cloudflare. Даже если все вкладки уже закрыты — по прямой ссылке (Cloudflare сам подставит ваш аккаунт; если попросит — войдите):
   **https://dash.cloudflare.com/?to=/:account/workers/services/view/dashboard-ozon/production/settings**
   Если ссылка не открылась — руками: **dash.cloudflare.com** → слева **Compute** → **Workers & Pages** → в списке **dashboard-ozon** → вверху вкладка **Settings** (последняя в ряду Overview, Metrics, Deployments…).
2. Первый раздел страницы — **Runtime variables and secrets** (рядом выбрано Production — так и оставьте). Справа от заголовка нажмите **+ Add variable**.
3. Откроется окно **Add environment variable**:
   - вверху **Select environment**: **Production** отмечен — оставьте, **Previews** не отмечайте;
   - ниже пара полей **Key** и **Value**, справа от Value — галочка **Secret**;
   - кнопкой **+ Add** под полями добавляется ещё одна пара.

   Заполните три пары:

| Key | Value | Secret |
|---|---|---|
| `PAROL` | пароль для входа на страницу — придумайте **новый**: латиница и цифры, без пробелов, не короче 10 знаков, не имя и не год рождения. Запишите в заметку | ✅ отметить |
| `GITHUB_TOKEN` | строка `github_pat_…` из шага 6.1 | ✅ отметить |
| `GITHUB_REPO` | ваш-логин/dashboard-ozon — например `ivanov/dashboard-ozon` | ❌ не отмечать (это просто адрес папки) |

4. **Проверьте галочки Secret — их должно быть ровно две:**
   - строка `PAROL` — галочка Secret **стоит**;
   - строка `GITHUB_TOKEN` — галочка Secret **стоит** (это пропуск, его надо спрятать; без галочки он будет виден в настройках открытым текстом);
   - строка `GITHUB_REPO` — галочки **нет** (это просто адрес папки, прятать нечего).

   Нажмите синюю кнопку справа внизу — на ней написано **Add 3 variables and deploy**.

После нажатия в разделе появится таблица из трёх строк: `GITHUB_REPO` — Variable с адресом папки, `GITHUB_TOKEN` и `PAROL` — Secret с надписью «Value encrypted» (спрятаны). Над таблицей может появиться жёлтая плашка «Update your Wrangler configuration…» — закройте её крестиком, делать ничего не нужно: программа сама сохраняет эти настройки при обновлениях.

**Снимки экрана с паролем, пропуском или ключами никому не отправляйте** — даже тому, кто помогает с установкой. Если нужна помощь — сначала закройте значения (сотрите или прикройте), потом снимайте.

**Как понять, что получилось:** на этой же странице Cloudflare справа вверху есть синяя кнопка **Visit** со стрелочкой — нажмите её. Откроется ваша ссылка из шага 5: теперь это тёмная страница входа «Dashboard Ozon» с полем **«Пароль»**.

## Шаг 7. Первый вход и настройки

1. Откройте свою ссылку, введите пароль. Браузер запомнит вход на 30 дней.
2. Откройте **Настройки** и заполните:
   - **Закупка** каждого товара — себестоимость одной штуки с доставкой до склада Ozon. Без закупки прибыль по товару будет завышена: такие поля подсвечены оранжевым;
   - **Фулфилмент** — если платите за упаковку и отгрузку, за штуку;
   - **Налог** — ваша система и ставки. Если ставка менялась — добавьте строку «с новой даты»;
   - **Свои расходы** — зарплаты, бухгалтерия, аренда в месяц;
   - **Название магазина**.
3. Нажмите **Сохранить**. Пересчёт запустится сам, новые цифры появятся через 3–5 минут.

Удалите заметку с ключами — они больше не нужны.

## Как этим пользоваться

- **Обзор** — прибыль за вчера, 7 дней, месяц или 30 дней: куда ушли деньги, выручка и прибыль по дням, товары. Нажмите на столбик — откроется этот день.
- **Факт** — реальные деньги по начислениям Ozon за месяц. Он считает по дате начисления, а «Обзор» — по дню заказа, поэтому за одни даты они не совпадают: деньги за заказ приходят через одну-две недели.
- **Товары** — сколько остаётся с одной штуки до и после рекламы.
- **Настройки** → **Пересчитать сейчас** — если поменяли цену или закупку и не хотите ждать утра. **Обновить инструмент** — подтянуть свежую версию; ваши настройки и история не меняются.

## Если что-то не так

- **Страница пишет «Данных пока нет»** — первый сбор ещё идёт или упал: проверьте вкладку **Actions** на GitHub.
- **Красный крестик в Actions с «HTTP 403» или «HTTP 401»** — ключ Ozon неверный или удалён: создайте новый и замените секрет (шаг 3).
- **Настройки «недоступны»** — проверьте `GITHUB_TOKEN` и `GITHUB_REPO` на Cloudflare (шаг 6). Если прошёл год — выпустите новый ключ GitHub.
- **Забыли пароль страницы** — задайте новый `PAROL` в Cloudflare (шаг 6.2).
