# Dashboard Ozon — установка

Dashboard Ozon каждое утро сам забирает данные вашего магазина из Ozon и показывает, сколько вы заработали чистыми: по дням, по месяцам и по каждому товару. Робот работает в вашей **закрытой папке на GitHub** (бесплатно), а страница открывается по личной ссылке — в России без VPN.

**Ваши цифры заперты вашим паролем.** Робот запирает их перед отправкой, а отпирает только ваш браузер, когда вы вводите пароль. Сервер, который показывает страницу, видит лишь бессмысленный шифр — ни его владелец, ни кто-либо ещё ваши продажи и прибыль прочитать не может. Ключи Ozon остаются только у вас на GitHub.

**Что понадобится:** доступ владельца к кабинету продавца Ozon, почта, примерно 45 минут. Всё делается в браузере, одинаково на Mac и Windows. Удобнее с компьютера.

**Если закрыли вкладку и не знаете, куда вернуться:** **github.com** → справа вверху значок вашего аккаунта → **Your repositories** → `dashboard-ozon`. В каждом шаге ниже есть и прямые ссылки.

**Главное правило:** ключи, пропуски и пароль, которые вы создадите, — как пароль от кабинета. Вставляйте их только туда, куда сказано в инструкции. Никому не пересылайте, в чаты не вставляйте, снимки экрана с ними не делайте. Пока идёте по шагам, держите их в одной заметке на своём компьютере, а в конце заметку удалите.

## Шаг 1. Ключи Ozon

### 1.1. Ключ продавца (обязательно)

1. Откройте **seller.ozon.ru** → **Настройки** → в разделе **API интеграции** выберите **Seller API**.
2. Нажмите **Сгенерировать ключ** (или **Добавить ключ**). Откроется окно «Генерация ключа».
3. **Название ключа:** `Dashboard Ozon`.
4. **Цель использования ключа** (обязательное поле): выберите **«Для личного использования»** — инструмент работает в ваших аккаунтах и только для вас.
5. В списке ролей прокрутите вниз, найдите **Admin read only** и поставьте галочку **только у неё** — это доступ только на чтение. Ключ с правом изменений этому инструменту не нужен и опасен.
6. Вкладку **«Разрешённые сети»** не заполняйте: GitHub каждый раз заходит с разных адресов, и ключ с привязкой к адресам работать не будет. Нажмите **Сгенерировать**.
7. Ozon покажет **Client-Id** (число) и **API-ключ** (длинная строка). Ключ показывается **один раз** — сразу сохраните оба значения в заметку.

### 1.2. Ключ рекламного кабинета (желательно)

Без него Dashboard не увидит расходы на рекламу, и прибыль будет завышена.

1. Там же, в **Настройки** → **API интеграции**, выберите **Performance API**. Ключи рекламы здесь живут внутри «сервисных аккаунтов»: сначала аккаунт, в нём — ключ.
2. Нажмите синюю кнопку **Создать аккаунт** справа вверху. Ozon ничего не спросит и ничего не покажет — просто вверху таблицы появится новая строка с номером аккаунта, сегодняшней датой и **0** в колонке «Кол-во ключей». Так и должно быть: аккаунт пока пустой.
3. Нажмите на **номер этого нового аккаунта** (в первой строке) — откроется сам аккаунт.
4. Внутри нажмите синюю кнопку **Добавить ключ**.
5. Появятся две строки — **Client ID** и **Client Secret**, справа у каждой кнопка «скопировать». Скопируйте обе по очереди в заметку. Secret показывается **один раз**.
6. Если в таблице уже есть другие сервисные аккаунты — не трогайте и не удаляйте их: ими могут пользоваться другие ваши сервисы.

## Шаг 2. Своя копия на GitHub

**Что здесь происходит.** На GitHub лежит образец — папка с программой Dashboard Ozon, открытая всем. Вы делаете себе её **копию** — свою папку, закрытую от всех, кроме вас. В вашей папке каждое утро сам будет просыпаться робот: заходить в Ozon с вашими ключами, всё считать и складывать результат туда же.

### 2.1. Зарегистрироваться на GitHub (если аккаунта ещё нет)

GitHub — бесплатный сервис, где хранятся программы. Аккаунт нужен один раз.

1. Откройте **https://github.com/signup** — регистрация.
2. GitHub по очереди спросит:
   - **Email** — ваша почта (на неё придёт код);
   - **Password** — придумайте пароль, не короче 8 знаков, с цифрой и маленькой буквой. Запишите его;
   - **Username** — имя пользователя латиницей, его называют **логин**. Например `ivanov-shop`. Он будет в адресах — запишите его, дальше понадобится;
   - **Country/Region** — ваша страна;
   - рассылку можно не отмечать.
3. Нажмите **Continue** / **Create account**. GitHub может попросить решить простую картинку-задачку — это проверка, что вы не робот.
4. На почту придёт письмо с **кодом** из 8 цифр — впишите его на странице GitHub.
5. Если после этого GitHub задаёт вопросы о вас («сколько человек в команде», «чем интересуетесь») — их можно пропустить (**Skip**). Если предлагает выбрать тариф — выбирайте бесплатный (**Free**).

**Как понять, что получилось:** вы на главной странице GitHub, справа вверху круглый значок — это ваш аккаунт.

### 2.2. Сделать копию образца

1. Убедитесь, что вошли в свой аккаунт GitHub (справа вверху ваш значок; если нет — **Sign in** и войдите с почтой и паролем).
2. Откройте ссылку: **https://github.com/nikitabuilding-code/dashboard-ozon/generate** — откроется форма «Create a new repository».

   **Не пугайтесь чужого имени в ссылке.** `nikitabuilding-code` — это автор образца, ссылка ведёт на образец, а не в чужой аккаунт. Копия создастся **в вашем** аккаунте: в поле **Owner** формы будет стоять ваш логин. Автор образца вашу копию не видит и ничего в ней не может изменить. Если GitHub вместо формы просит войти — войдите и откройте ссылку ещё раз.
3. Форма «Create a new repository» состоит из трёх частей. Сверху вниз:
   - **Start with a template** — там уже выбрано `nikitabuilding-code/dashboard-ozon`, переключатель **Include all branches** — Off. Ничего не трогайте;
   - раздел **1 General**:
     - **Owner** — там уже стоит ваш логин, не трогайте;
     - **Repository name** — наберите `dashboard-ozon` на клавиатуре (не копируйте: в имя может попасть лишний пробел). Под полем появится зелёная надпись «dashboard-ozon is available» — значит, имя свободно;
     - **Description** — оставьте пустым;
   - раздел **2 Configuration** → **Choose visibility** — справа кнопка с выпадающим меню. Проверьте, что выбрано **Private** (с замочком): нажмите на кнопку, в меню отметьте **Private**. Не **Public** — в папке будут ваши цифры и закупочные цены.
4. Внизу нажмите зелёную кнопку **Create repository**.

**Как понять, что получилось:** откроется страница вашей копии, рядом с названием серая надпись **Private**. **Сохраните эту страницу в закладки** (Mac — Cmd+D, Windows — Ctrl+D): к ней вы вернётесь в шагах 5 и 6.

## Шаг 3. Пропуск для настроек

**Что здесь происходит.** На странице Dashboard есть вкладка «Настройки»: там вы укажете закупку, налог и свои расходы. Чтобы страница могла сохранить их в вашу папку на GitHub, ей нужен **пропуск** в эту папку.

1. Откройте ссылку: **https://github.com/settings/personal-access-tokens/new** — форма нового пропуска (по-английски «token»).
2. Заполните:
   - **Token name** — `Dashboard Ozon`. Если GitHub пишет зелёным «is available», имя подходит;
   - **Description** — оставьте пустым; **Resource owner** — ваш логин, не трогайте;
   - **Expiration** — нажмите (по умолчанию «30 days»), выберите **Custom** и в появившемся поле даты поставьте дату **через год**. «No expiration» (бессрочно) не берите. Поставьте себе в календарь напоминание за неделю до конца — выпустить новый: когда пропуск истечёт, «Сохранить» на странице перестанет работать — выпустите новый и замените секрет `PROPUSK_GITHUB`;
   - **Repository access** — отметьте третий кружок **Only select repositories** → кнопка **Select repositories** → в списке галочка **только** у своей копии `dashboard-ozon` (с замочком) → закройте список крестиком. Ниже появится «Selected 1 repository»;
   - ниже раздел **Permissions** → кнопка **+ Add permissions** → в списке отметьте **Contents** и **Actions** (удобно через поиск). Они появятся строками с выбором **Access: Read-only** — у обоих переключите на **Read and write**. Строку **Metadata** (с пометкой Required) GitHub добавит сам — её не трогайте, ей хватает Read-only.

   **Не пугайтесь слова «write» (запись).** Этот пропуск — к вашей папке на GitHub, **не к кабинету Ozon**. Ключ Ozon вы создали в шаге 1 только на чтение — с ним ничего в кабинете изменить нельзя, и этот шаг его не меняет. А «запись» здесь нужна для двух вещей:
   - **Contents** — чтобы страница «Настройки» могла сохранить в вашу папку то, что вы ввели: закупку, налог, свои расходы. Без этого кнопка «Сохранить» не сработает;
   - **Actions** — чтобы кнопки «Пересчитать сейчас» и «Обновить инструмент» могли запустить робота в вашей папке, не дожидаясь утра.

   Пропуск действует **только на одну папку** (остальные ваши папки на GitHub ему недоступны). Вы положите его в сейф GitHub (шаг 5), а робот передаёт его странице только запертым вашим паролем — без пароля им не воспользоваться.
3. Внизу зелёная кнопка **Generate token** → в окошке подтверждения ещё раз **Generate token**.
4. Появится строка, начинается с `github_pat_` — нажмите значок копирования справа и вставьте её в заметку. Показывается один раз. Снимок экрана с этой строкой не делайте и никому не отправляйте.

## Шаг 4. Адрес вашего Dashboard

**Что здесь происходит.** Вы получаете **личный адрес** своей страницы и **пропуск робота** — по нему сервер принимает данные только от вашего робота, и больше ни от кого.

1. Откройте **https://vibeforge7.com/dashboard-ozon/** — страница «Получить адрес для своего Dashboard».
2. Нажмите синюю кнопку **Получить адрес**.
3. Появятся два значения, у каждого кнопка **Копировать**:
   - **Адрес вашего Dashboard** — ссылка вида `https://vibeforge7.com/dashboard-ozon/abcd2efgh3jk/`. Скопируйте в заметку и сохраните в закладки на компьютере и телефоне (на iPhone: Safari → «Поделиться» → «На экран Домой» — откроется как приложение);
   - **Пропуск робота** — длинная строка с двоеточием. Скопируйте в заметку: она понадобится в шаге 5.
4. **Пропуск показывается один раз.** Закрыли страницу, не скопировав, — получите новый адрес заново (кнопка снова выдаст пару).

**Как понять, что получилось:** в заметке есть адрес Dashboard и пропуск робота.

## Шаг 5. Пароль и сейф GitHub

**Что здесь происходит.** Робот берёт ключи из **секретов** — закрытого сейфа внутри вашей папки. Положили ключ туда — и даже вы его больше не увидите, его видит только робот. Здесь же лежит **ваш пароль**: им робот запирает цифры, им же вы открываете страницу.

### 5.1. Придумайте пароль

Это пароль от вашего Dashboard — вы будете вводить его на странице. Он должен быть **стойким**: запертые цифры лежат на сервере, и слабый пароль со временем можно подобрать, стойкий — нет.
- **не короче 12 знаков**, есть и буквы, и цифры;
- **не** имя, **не** дата рождения, **не** слово из словаря, **не** пароль от другого сайта;
- пример стойкого: `vK7-pr2m-Lq9x-4tza` (этот не берите — придумайте свой).

Запишите его в заметку. Сам GitHub примет в сейф любой пароль — проверит его робот при первом запуске (шаг 6): если пароль слишком простой, у запуска будет красный крестик и надпись «пароль слишком простой».

### 5.2. Положите всё в сейф

1. Откройте свою копию на GitHub (закладка из шага 2; потеряли — github.com → круглый значок справа вверху → **Repositories** → `dashboard-ozon` с серой надписью **Private**).
   Вверху вкладка **Settings** → в меню слева **Secrets and variables** → **Actions** → зелёная кнопка **New repository secret**. Откроется форма с двумя полями.
2. Поле **Name** — имя из таблицы, поле **Secret** — значение из заметки. Потом зелёная кнопка **Add secret**.
3. Повторите для каждой строки — на открывшейся странице каждый раз жмите зелёную **New repository secret**.

| Name (копируйте отсюда) | Secret (из заметки) |
|---|---|
| `OZON_CLIENT_ID` | Client-Id ключа продавца — число |
| `OZON_API_KEY` | API-ключ продавца — длинная строка |
| `OZON_PERF_CLIENT_ID` | Client ID рекламы |
| `OZON_PERF_SECRET` | Client Secret рекламы |
| `PROPUSK_GITHUB` | пропуск из шага 3 — начинается с `github_pat_` |
| `DO_PROPUSK` | пропуск робота из шага 4 — строка с двоеточием |
| `PAROL` | ваш пароль из 5.1 |

Имена — точно так, большими латинскими буквами с подчёркиваниями. Лишний пробел в начале или в конце значения его сломает.

**Как понять, что получилось:** в списке **Repository secrets** семь строк с этими именами. Значений не видно — так и должно быть.

## Шаг 6. Первый запуск робота

**Что здесь происходит.** Робот сам будет просыпаться каждое утро. Но в первый раз его нужно разбудить вручную — чтобы он сразу забрал историю за 3 месяца и проверил, что ключи подходят.

1. Откройте свою копию на GitHub (закладка из шага 2) → вверху вкладка **Actions** → в меню слева **Сбор данных**.
   Если вместо страницы видите жёлтую плашку с кнопкой **I understand my workflows, go ahead and enable them** — нажмите её и снова выберите «Сбор данных».
2. Откроется страница **«Сбор данных»**: слева список (выделено «Сбор данных»), в центре надпись «0 workflow runs» и «This workflow has no runs yet» — робот ещё ни разу не запускался. Сверху может висеть голубая плашка «Help us improve GitHub Actions» — не обращайте внимания.
3. Справа от заголовка «Сбор данных» — зелёная кнопка **Run workflow**. Нажмите её. Запуска ещё не будет: под кнопкой появится белая рамка с заголовком **«Use workflow from»**, в ней поле **main** и внизу две кнопки — серая **Cancel** и зелёная **Run workflow**.
4. Нажмите зелёную **Run workflow** внизу этой белой рамки (рядом с Cancel). Поле main не трогайте. Рамка закроется.
5. Через 5–10 секунд вместо «no runs yet» появится строка «Сбор данных» с **жёлтым кружком** — робот запущен. Нажмите на неё — откроется страница запуска «Сбор данных #1».
6. На этой странице в поле **Status** сначала стоит **Queued** — «в очереди»: GitHub ищет для робота свободную машину, от нескольких секунд до пары минут. Потом **In progress** — робот работает. **Первый раз это около 5 минут** (на пробной установке — 4 мин 37 с), если Ozon отвечает медленно — до 15. Каждое следующее утро робот докачивает только свежие дни и справляется за 1–2 минуты. Страницу можно не обновлять — статус сменится сам. Кнопку **Cancel workflow** справа вверху не нажимайте — она остановит робота.

**Как понять, что получилось:**
- **зелёная галочка** у строки — всё хорошо. Для уверенности нажмите на строку → **sbor** → раскройте шаг **«Сбор и расчёт»**: внизу будут строки «· товары: … в кабинете», «· начисления: обновлено дней …», «· реклама: кампаний …» и последняя — «страница обновлена: данные заперты вашим паролем и отправлены». Строк со значком ⚠ быть не должно. Строка «новые товары без закупки» — нормальная подсказка: закупку впишете в шаге 7. Серые строки `DeprecationWarning` в самом низу — служебное предупреждение GitHub, на работу не влияют;
- **красный крестик** — нажмите на строку, откройте шаг с крестиком и пришлите снимок экрана тому, кто помогает с установкой. Чаще всего это опечатка в секрете (шаг 5). Если написано «пароль слишком простой» — замените секрет `PAROL` на стойкий и запустите снова.

## Шаг 7. Первый вход и настройки

1. Откройте **адрес вашего Dashboard** из шага 4 (из заметки или закладки). Не сохранили — он есть в отчёте робота: своя копия на GitHub → **Actions** → последний запуск «Сбор данных» → **sbor** → «Сбор и расчёт» → в конце строка «адрес вашего Dashboard: …».
2. Появится окно «Dashboard Ozon» с полем **Пароль** — впишите пароль из шага 5.1 (тот, что в секрете `PAROL`). Галочка «Запомнить на этом устройстве на 30 дней» — чтобы не вводить его каждый раз. Нажмите **Открыть**.
3. Оранжевая плашка «Укажите закупку…» → **Открыть настройки**. Заполните:
   - **Закупка** каждого товара — себестоимость одной штуки с доставкой до склада Ozon. Без закупки прибыль по товару будет завышена: такие поля подсвечены оранжевым;
   - **Фулфилмент** — если платите за упаковку и отгрузку, за штуку;
   - **Налог** — ваша система и ставки. Если ставка менялась — добавьте строку «с новой даты»;
   - **Свои расходы** — зарплаты, бухгалтерия, аренда в месяц;
   - **Название магазина**.
4. Нажмите **Сохранить**. Пересчёт запустится сам, новые цифры появятся через 3–5 минут — обновите страницу.

Удалите заметку с ключами: адрес Dashboard пусть останется в закладках, пароль — в памяти или в менеджере паролей.

## Как этим пользоваться

- **Дашборд** — прибыль за вчера, 7 дней, месяц или 30 дней: куда ушли деньги, выручка и прибыль по дням, товары. Кнопка **«Выбрать дату»** (значок календаря) или нажатие на столбик открывает любой день — вся страница, включая товары, покажет этот день.
- **Фактическая прибыль / убыток** — реальные деньги по начислениям Ozon за месяц. Он считает по дате начисления, а «Обзор» — по дню заказа, поэтому за одни даты они не совпадают: деньги за заказ приходят через одну-две недели.
- **Товары** — сколько остаётся с одной штуки до и после рекламы.
- **Настройки** → **Пересчитать сейчас** — если поменяли цену или закупку и не хотите ждать утра. **Обновить инструмент** — подтянуть свежую версию сразу, не дожидаясь утра.
- **Обновления приходят сами:** каждое утро перед сбором робот подтягивает свежую версию программы. Ваши настройки и история при этом не меняются.

## Если что-то не так

- **Страница пишет «Данных пока нет»** — первый сбор ещё идёт или упал: проверьте вкладку **Actions** на GitHub.
- **Красный крестик в Actions с «HTTP 403» или «HTTP 401»** — ключ Ozon неверный или удалён: создайте новый и замените секрет (шаг 3).
- **Настройки «недоступны»** — нет секрета `PROPUSK_GITHUB` или у пропуска прошёл срок. Выпустите новый (шаг 3), замените секрет и запустите сбор (шаг 6) — страница подхватит его.
- **Вместо фото товаров пустые тёмные квадраты** — картинки режет расширение браузера, обычно блокировщик рекламы. Проверка: откройте страницу в окне инкогнито (Mac: Cmd+Shift+N, Windows: Ctrl+Shift+N) — там фото будут. Чтобы были и в обычном окне, добавьте адрес своей страницы в исключения блокировщика. На расчёты это не влияет.
- **Забыли пароль** — вскрыть запертые цифры без пароля нельзя никому, но ничего не потеряно: всё лежит в вашей папке на GitHub. Задайте новый секрет `PAROL` (шаг 5) и запустите сбор (шаг 6) — робот запрёт цифры новым паролем.
- **Страница пишет «Данных пока нет»** — робот ещё ни разу не присылал данные: проверьте вкладку Actions на GitHub (шаг 6) и строку «страница обновлена».
